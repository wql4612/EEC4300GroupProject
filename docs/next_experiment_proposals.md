# 下一轮研究方案草案

本轮没有修改算法或启动在线实验。P3 已关闭，三个条件均未达到原放行条件。以下仅为待审草案。实际比较先冻结模型、基础 Prompt、候选处理、槽位、Seed、组顺序和基础设施重跑规则。官方 RR、VR、NR 与 P3 放行门槛沿用已注册定义。 [P3 深度分析](p3_deep_analysis.md) · [预注册方案](p3_validation_plan.md)

可用于下一轮独立开发的现有保留池只剩四组。若获准使用这四组，实验仅用于机制筛查，无法验证按五组定义的稳健性。当前官方全集经复算无法补出第五组；若将来另提数据生成协议，须先确认评估兼容性并单独审核。P3、Pilot 和正式组均不用于调参。 [独立数据可行性审计](independent_dataset_feasibility.md)

## 1. 结构化有效历史

- **问题与机制。** 现有历史反馈会回放不可用表达式，也会多次回放同一机械键。候选处理沿用官方可用的在线 AST 和机械键逻辑。对满足公开 Grammar 且通过公开观测检查的候选按机械键去重，保留最近至多四个。其余候选仅通过固定诊断标签表示，避免再次放入原始非法文本。空历史采用固定短提示。
- **关系、预期和风险。** 这项改动属于候选记忆接口，可由固定温度、Basic ACB 和 Full FSCB 共享。预期后三槽的重复率降低，新增键及组覆盖上升。过滤可能消除有助于定位错误的上下文，长度变化也可能解释差异，因此记录 Token 及 Q1 平衡，另记两种历史所携带的失败诊断。
- **最小验证及资源。** 若获准，在四个保留组上比较原始历史和结构化历史，以 P1 为共同基础、固定温度 0.6、3 个预先冻结 Seed、每组四槽，计划 96 次。已有日志可先离线验证历史构造，不能用于推断改动后的生成结果。RTX 4060 8 GiB，启动前至少 4,096 MiB 可用。按 P3 180 请求约 52 秒估计，96 槽生成约半分钟，预留 2–5 分钟加上日志和评分，实际受 Token 变化影响。
- **隔离。** 可见观测用于单个候选的在线一致性检查。历史标签与去重仅取当前轨迹状态。离线答案和 RR 不参与每槽决定。

第三轮补充契约：原始 History 由 Parser 接受的原文按发生顺序追加；结构化版本先经官方空间和观测 Validator，再取机械键。每组用独立的全程有效键集合记账，展示窗口只保存最近四个首次有效的不同键，重复不刷新次序。由局部白名单映射失败标签：不可解析、越界、观测不一致、缺机械键。基础设施响应只作运行记录，重复候选仅记去重事件，历史不包含失败原文、真值表或答案信息。空历史统一用原模板的 None。诊断建议仅展示最近一次失败的标签，首次调用保持同一空历史。

公平比较以同一组、Seed、渲染位置、最大上下文和输出预算配对。预先固定有版本的同源离线 Token 计数器和公共历史预算，建议每臂上限 128 输入 Tokens，标签计入额度，从最旧完整条目裁减。若事前无法核验 Token 计数器，使用事先同意的保守字符上限并从返回元数据报告真实 Token，避免宣称严格等 Token。原始轨迹只用于证明机械键过滤和窗口行为；新增对照可用诊断关闭臂区分筛选与诊断文字效应。 Controller 与历史夹具（私有证据 `results/p3-third-review-20261126/controller-offline-tests.log`）

## 2. Grammar 约束与观测自检

- **问题与机制。** P3 有 97 槽越界，另有 25 槽虽在空间内却与观测不一致。将生成输出限制为只包含公开算符、变量及深度约束所允许的 AST。实验前用合成夹具确认受支持的本地生成接口确实执行限制。另一个可选干预是一次请求内用固定指令核对所有给定观测，仅产出一个候选。两个变化应分开测试。
- **关系、预期和风险。** 约束作用于候选生成器，Controller 仍独立。若合规率上升而 H5 型失败持续，则该分支应转向验证观测核对，先复核输出转换是否保留原候选及官方评分等价性。若本地接口无法在一个请求内可靠实现此语法，保留方案未通过的记录。闭世界约束可能使 Controller 收益变小，轨迹预算也不能包含隐藏的拒绝重采样。
- **最小验证及资源。** 优先用无模型的公开 Grammar 正反例验证转换和边界。若方案 1 与 2 都获准用同一四组，把两项合并为一次历史 × Grammar 的 2×2 预注册筛查，共 192 槽。观测自检留给独立、后来冻结的研究条件。RTX 4060 8 GiB，192 槽按 P3 粗估约 55 秒生成，含准备和评分预留 3–8 分钟。裁决同时看空间内率、观测一致率、官方 RR 和每槽首次有效键。
- **隔离。** Grammar 只来自公开任务规范。候选层不得读答案键、答案数、兼容列表或离线评分。观测自检只对模型这次提交的候选核对公开观测。

第三轮接口结论：安装的 llama-server 帮助列出 Grammar 与 JSON Schema 选项。Ollama v0.40.14 的 GenerateRequest 接收 format，生成路由传给 Completion；后端对 JSON 对象 format 设置 json_schema，对字符串 json 使用通用 JSON Grammar。当前冻结采集器未发送 format。由此可确认本地版本支持结构化解码接口，尚未在 Qwen 上验证特定 Boolean Schema 的端到端约束。后端 CLI 的原生 GBNF 选项也不能推定为 Ollama 的公开 HTTP 字段。 安装二进制帮助（私有证据 `results/p3-third-review-20261126/ollama-grammar-help.log`） · [v0.40.14 API 类型](https://github.com/ollama/ollama/blob/v0.40.14/api/types.go) · [v0.40.14 生成路由](https://github.com/ollama/ollama/blob/v0.40.14/server/routes.go) · [v0.40.14 后端映射](https://github.com/ollama/ollama/blob/v0.40.14/llm/llama_server.go)

建议只在获批的新条件里测试 JSON 对象内一个 expression 字段，以公共 Grammar 枚举的十个机械键的合法代表式构造 enum，同一表用于所有组。先离线验证一一映射和官方 Parser 的确定性适配，再在批准的能力试验中确认 Schema 执行。保留原始 JSON、适配产物和接口拒绝证据。对照也使用相同输出信封和 Parser 适配，仅放宽 expression 值约束。通用 JSON 或纯 Prompt 提醒只作格式／软约束，不记为硬 Boolean 语法控制。观测自检独立成另一条件：同一请求内要求按公开行核对且只返回一个候选，收到后本地 Validator 仅检查该候选一次。即使截断、格式错误或观测失配，照常记账，严禁隐式修补、再调用或拒绝后重采样。

## 3. 针对可观测发现反馈的 Controller 对照

- **问题与机制。** 当前历史可用窗口和正反馈集中于少数组，六臂可能缺少稳定曝光。保留 Basic ACB、Full FSCB 和既定消融，先用合成反馈或既有轨迹上的离线日志模拟验证可用 arm 判定、预热、组内状态重置、跨组参数更新及奖励范围。离线模拟只能验证状态机，无法推断新 Prompt 或 arm 的反事实收益。
- **关系、预期和风险。** Full 用结构档案提供前沿提示和边际覆盖奖励，Basic 用原始温度 Bandit。先检查结构提示目标命中、首次跨桶发现和各臂实际暴露，再看官方 RR。暴露不足或稀有组没有恢复时，任何提升结论都需保留不确定性。随机和固定对照共享同一生成器及槽预算。
- **最小验证及资源。** 当前只做 CPU 离线夹具，预计半小时内可完成状态检查的人工复核，无 GPU 需求。独立放行达到原门槛且取得单独 Pilot 授权后，沿用原 5 组 × 8 槽 × 8 条件、最多 320 请求的 Pilot 验证设计。以 P3 速度作下限估计，约 1.5 分钟生成，含组切换、遥测及离线评分预留 5–15 分钟。后续效应验证采用原正式矩阵及预定多 Seed。
- **隔离。** 决策与奖励只使用公开观测、在线 Validator、候选新颖性、结构覆盖及动作历史。官方答案、恢复数量和 RR 仅进入独立离线评估。
